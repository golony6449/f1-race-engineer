# 직전 랩 기준과 코너 탈출 즉시 코칭 계획

일감: SCRUM-94

## 배경 (사용자 요청 2026-11-14)

1. 기준 랩이 내 최고 랩이면 타이어가 닳을수록 계속 느려 보인다. **직전 랩 기준으로, 모든 선수의 코너 기록 중
   최고를 기준으로 삼는다.**
2. 무전이 한꺼번에 몰려 나온다. **코너를 탈출하면 바로 가이드한다.**

무전을 `_pending`에 쌓아 두었다가 긴 직선에서 한 번에 내보낸다. 스즈카 S자(2~7번)처럼 코너가 붙은 구간은 전부 미뤄진다.
코칭 무전 TTL은 "그 코너 다음 진입 전까지"(거의 한 랩)라 늦어도 버려지지 않는다.

## Global Constraints

- 주석·문서·커밋 메시지는 한국어. 테스트는 `uv run pytest`.
- 의존성 파일은 바꾸지 않는다. 공용 `conftest.py`는 만들지 않는다.
- 안전 경고·박스 지시 등 다른 무전 종류의 동작은 바꾸지 않는다. 리프트 앤 코스트(`defer_until_straight` 재사용)도 그대로 둔다.
- 타임 트라이얼(`NON_AI_SESSION_TYPES`)은 상대가 없으므로 지금처럼 **내 최고 랩**을 기준으로 둔다.

### 작업 1: 직전 랩 기준(모든 선수 코너 최고)

**Files:**
- Modify: `src/f1re/coaching/reference.py`
- Modify: `src/f1re/pipeline.py`
- Test: `tests/coaching/test_reference.py`

1. `ReferenceSet.best_for(corner)`의 새 규칙(타임 트라이얼이 아닌 세션):
   - 후보는 **차마다 이번 세션에서 가장 최근에 끝낸 유효 랩 하나**(랩 번호가 가장 큰 것, 같으면 나중에 넣은 것).
     내 차도 포함한다.
   - 그 후보들 중 그 코너 구간 시간(`corner_duration_ms`)이 가장 짧은 랩을 기준으로 쓴다.
   - 출처 문자열은 기존 값을 그대로 쓴다: 고른 랩이 내 차면 `SOURCE_SELF`, 다른 차면 `SOURCE_FASTEST_CAR`
     (화면·근거 호환. docstring에 뜻이 "직전 랩 중 그 코너 최고"로 바뀌었다고 적는다).
2. 이번 세션 랩과 저장소에서 불러온 랩을 구분한다. `update(trace, *, stored: bool = False)`처럼 표시하고,
   `pipeline._adopt_reference`는 `stored=True`로 넣는다. **이번 세션 랩이 하나라도 있으면 저장 랩은 후보에서 뺀다.**
   이번 세션 랩이 없을 때(첫 랩)만 저장 랩을 지금 규칙(내 최고·최속차 최고 중 코너별 빠른 쪽)으로 쓴다.
3. 타임 트라이얼 세션은 지금 규칙(내 최고 랩) 그대로.
4. `prune()`은 차마다 **최고 랩과 최근 랩**을 남긴다(둘이 같으면 하나). `best_lap(source)`(저장·집중 코너가 씀)는
   지금처럼 최고 랩을 돌려준다.
5. 레이스 1랩 제외·무효 랩 제외는 지금 그대로.
6. 테스트:
   - 내 차 랩 2(최고), 랩 5(최근, 더 느림)와 다른 차 A 랩 5(그 코너 더 빠름) → 기준은 A 랩 5, 출처 `fastest_car`.
   - 다른 차 A 랩 2가 그 코너에서 가장 빠르지만 A 랩 5가 최근이면 A 랩 2는 후보가 아니다.
   - 내 최근 랩이 그 코너에서 가장 빠르면 출처 `self`.
   - 저장 랩만 있으면 지금 규칙, 세션 랩이 하나 생기면 저장 랩은 빠진다.
   - 타임 트라이얼은 내 최고 랩.
   - `prune()` 뒤에도 같은 결과.

### 작업 2: 코너 탈출 즉시 코칭, 늦은 코칭은 버리기

**Files:**
- Modify: `src/f1re/coaching/coach.py`
- Modify: `src/f1re/radio/queue.py`
- Modify: `src/f1re/config.py`
- Modify: `config/default.toml`
- Test: `tests/coaching/test_coach.py`
- Test: `tests/radio/test_queue.py`

1. `Coach._coach_corner`: 코너 탈출을 지난 첫 샘플에서 만든 코칭 무전을 **미루지 않고 바로** 내보낸다
   (`defer_until_straight`·`_pending`을 코칭에 쓰지 않는다. 쓰는 곳이 없어지면 `_pending` 관련 코드를 정리한다).
2. 코칭 무전 유효 시간: `[global]`에 `coaching_ttl_s = 5.0`(설정·`AppConfig`·`CoachConfig`에 추가, 0보다 커야 함).
   `_coaching_ttl_ns`는 이 값을 쓴다. 5초 안에 못 말하면 큐가 만료로 버린다(기존 drop 기록 경로 그대로).
   지금의 "다음 진입 전까지" 계산은 지운다.
3. `RadioQueue.push`: 새 무전이 코칭(`RadioKind.COACHING`)이면, 대기 중인 **이전 코칭 무전**을 큐에서 빼고
   drop 처리기에 알린다(이유 문자열 `"superseded"`; 처리기 시그니처가 이유를 받지 않으면 기존 방식에 맞게 확장하고
   `radio_messages.dropped_reason`에 남게 한다). 재생 중인 무전은 끊지 않는다. 다른 종류 무전은 건드리지 않는다.
4. `defer_s` 설정과 `defer_until_straight` 함수는 리프트 앤 코스트(`src/f1re/coaching/lift_coast.py`)가 쓰므로 그대로 둔다.
5. 테스트:
   - 실제 표본처럼 코너 2~6이 붙은 구간(다음 코너 브레이크까지 3초 미만)에서도 각 코너 탈출 샘플에서 바로 무전이 나온다.
   - 코칭 무전 `ttl_ns`가 5초다.
   - 큐에 코칭 A가 대기 중일 때 코칭 B를 넣으면 A는 `superseded`로 버려지고 B만 남는다. 안전 경고가 대기 중이면 그대로 남는다.
   - 5초가 지난 코칭은 `next()`에서 만료로 버려진다.

## Review Focus

1. 타임 트라이얼이 아닌 세션에서 기준이 "차마다 최근 유효 랩" 중 코너별 최고인가. 오래된 빠른 랩이 섞이지 않는가.
2. 이번 세션 랩이 생기면 저장소에서 불러온 랩이 후보에서 빠지는가. 첫 랩에서는 저장 랩으로 코칭할 수 있는가.
3. 코칭이 코너 탈출 직후 바로 큐에 들어가는가. 5초를 넘긴 코칭이 재생되지 않는가.
4. 새 코칭이 대기 중인 옛 코칭만 밀어내고, 안전 경고·박스 지시 등 다른 무전은 건드리지 않는가.
5. `prune()`·저장·불러오기 뒤에도 기준 선택이 같은가.
