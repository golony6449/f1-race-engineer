# 한국어 AI 레이스 엔지니어 설계 (F1 25)

- 작성: 2026-11-12, 마스터 세션(사용자와 브레인스토밍)
- 참고 분석: 비공개 문서(공개 레포에 넣지 않음)
- 상태: 사용자 검토 대기

## 1. 무엇을, 왜

F1 25를 휠로 달리는 동안 **한국어로 짧게 말해 주는 레이스 엔지니어**를 만든다. 기존 앱(AI Race Engineer, Pacedex)은 한국어 보이스가 없고, 타이어·연료 같은 수치 안내가 중심이다. 이 앱은 **코너 공략 코칭**과 **추월 선택지 안내**에 무게를 둔다.

사용자가 원한 순간(사용자 말):
- 브레이크가 늦어 레코드라인을 벗어났을 때, 또는 너무 일찍 밟아서 코너에서 속도를 더 낼 수 있었을 때 가이드를 받고 싶다. 브레이킹을 포함해 스티어링까지, 코너 공략 전반을 봐 주면 좋겠다.
- 앞차를 추월하려 할 때 내가 할 수 있는 선택들을 말해 줬으면 좋겠다.

## 2. 목표 · 비목표 · 반목표

### 목표
1. 코너 공략 코칭: 브레이크, 턴인, 정점, 탈출, 라인을 기준 랩과 비교해, 시간을 많이 잃는 코너를 코너 탈출 직후에 짧게 말한다.
2. 추월 선택지: 앞차와 가까울 때 지금 고를 수 있는 방법을 1~2개 말한다.
3. 위험할 때만 음성 경고(타이어·연료·손상·페널티·세이프티카). 나머지 차량 상태는 화면에만.
4. 차량 상태와 서킷 지도를 옆 모니터·태블릿·휴대폰 브라우저에서 본다.
5. 서킷별 기록을 저장해, 다시 온 서킷에서는 첫 랩부터 코칭한다.

### 비목표 (이번에 하지 않음)
- 멀티플레이(온라인)
- 게임 화면 위 오버레이
- 무전 질의응답(음성 질문). 2단계에서 PC 에이전트와 함께 한다(9장).
- 리그·방송·셋업·랭킹 같은 기타 기능
- F1 25 이외의 게임
- 위성 사진 지도 배경

### 반목표 (기술적으로 돌아가도 실패인 것)
- **도움 안 되는 말.** 사용자는 쓸모없는 말을 하면 끈다고 했다. 이것이 가장 큰 실패 조건이다.
  - 모든 무전은 "어디서 + 무엇을 + 얼마나"를 갖춘다(예: "7번, 브레이크 5미터 늦게."). "타이어 관리하세요" 같은 막연한 말은 내보내지 않는다.
  - 근거가 약하면(기준 랩과의 차이가 작거나 데이터가 불확실하면) 말하지 않는다.
  - 같은 랩에 같은 지적을 두 번 하지 않는다.
- 코너 진입 중에 말이 겹쳐 운전을 방해하는 것.
- 말이 늦게 나와서 이미 지나간 코너 이야기를 하는 것.

## 4. 전체 구성 (사용자 결정)

```
[게임 PC] F1 25 ──UDP──────────────▶ [홈서버] 수신·파싱 → 상태 → 코칭·추월·경고 판단
             │                                   │            │
             └ 브라우저 /radio 탭 ◀── 음성 ───────┘            ├─ Qwen TTS API (클라우드)
               (게임 헤드셋으로 소리만)                          │
                                                               └─ 웹 대시보드
[태블릿·휴대폰·옆 모니터] 브라우저 ◀────────────────────────────────┘
```

- 게임이 UDP를 홈서버로 **바로** 보낸다(게임 텔레메트리 설정에서 서버 IP·포트 지정). PC에는 설치하는 프로그램이 없다.
- 홈서버가 파싱, 상태 계산, 기록 저장, 코칭·추월·경고 판단, 음성 합성(Qwen API 호출), 웹 제공을 모두 맡는다.
- 음성은 PC 브라우저의 무전 페이지(`/radio`)가 받아 재생한다. 기본 출력 장치(게임 헤드셋)로 나온다.
- 화면은 태블릿·휴대폰·옆 모니터 브라우저로 본다.
- 홈서버: i5-12500T, 메모리 32GB, GPU 없음, 리눅스. 자세한 운영 방식은 사용자 KB `kb/homeserver.md`.
- 게임 PC와 홈서버는 같은 집 네트워크에 있다고 본다(마스터 판단). 집 밖 서버(VPN 경유)는 범위 밖이다.
- 확인 필요(2단계): 스토리 모드(Braking Point)에서도 UDP 텔레메트리가 나오는지 첫 녹화 때 확인한다. 안 나오면 스토리 모드는 지원 대상에서 빼고 사용자에게 알린다.

## 6. 기능 설계

### 6.1 수신·파싱·녹화

- UDP 20777(설정 가능)로 받는다. 공통 헤더 29바이트를 읽고 `packetId`로 나눠 파싱한다(규격 요약은 reference-analysis 5장, 구현 전 EA 공식 문서로 대조).
- 파서는 패킷을 두 가지로 바꾼다.
  - **상태(스냅샷)**: 패킷 종류별 최신값. 차 22대 배열 그대로.
  - **사건(이벤트)**: Event 패킷과 상태 변화에서 만든 사건(피트, 추월, 페널티, SC·VSC, 날씨 변화, 랩 완료, 세션 시작·종료). 큐에 쌓아 놓치지 않는다.
- **원본 UDP 녹화를 처음부터 넣는다.** 받은 패킷을 수신 시각과 함께 파일로 저장하고, 같은 파이프라인에 다시 흘려 넣는 리플레이 모드를 둔다. 개발·테스트는 게임 없이 이 녹화로 한다.
- 진단 정보를 상태에 둔다: 초당 패킷 수, 마지막 패킷 ID·형식·길이, 마지막 수신 시각, 세션 UID. 대시보드에 "데이터 안 옴" 원인을 보여 준다.

### 6.2 랩·코너 기록

- 차마다 랩 거리(`lapDistance`) 기준으로 샘플을 기록한다: 속도, 스로틀, 브레이크, 스티어, 기어, 위치(x·z). 내 차는 휠 슬립 등 MotionEx 값도 기록한다.
- 기록은 랩 단위로 묶고, 무효 랩(트랙 이탈 경고, 피트 랩, 플래시백)은 표시해서 기준 랩 후보에서 뺀다.
- **코너 정의(서킷 데이터).**
  - 코너 번호는 공식 번호를 쓴다(사용자가 "3번"이라고 들었을 때 실제 3번 코너여야 한다).
  - 서킷마다 데이터 파일을 둔다: 트랙 ID, 코너별 공식 번호, 랩 거리 구간(진입~탈출), 다음 코너까지의 거리. 공개 자료(서킷 코너 목록)를 보고 직접 만든다. 다른 앱의 데이터 파일을 가져다 쓰지 않는다.
  - 데이터 파일이 없는 서킷은 기준 랩에서 감속·조향 구간을 자동으로 찾아 순서 번호를 붙인다. 이때는 "코너 3" 대신 "3번째 코너"처럼 공식 번호가 아님을 알 수 있게 말한다.
- **코너 지표**(코너마다, 기준 랩과 비교)

| 단계 | 지표 |
| --- | --- |
| 진입 | 브레이크 시작 지점(랩 거리), 최대 브레이크 압력, 브레이크를 놓는 모양(트레일 브레이킹: 턴인 이후까지 남는 압력) |
| 턴인 | 조향 시작 지점, 최대 조향량 |
| 정점 | 최저 속도와 그 위치, 조향 수정 횟수(조향 변화 방향이 바뀐 횟수, 잡음 제외) |
| 탈출 | 스로틀 다시 밟은 지점, 풀스로틀 지점, 탈출 속도(탈출 지점에서), 휠 슬립(내 차만) |
| 라인 | 기준 궤적에서 벗어난 최대 거리(진입·정점·탈출), 트랙 이탈 |
| 결과 | 코너 구간 시간 손실(진입~탈출, 랩 거리 기준으로 보간한 시간 차) |

- 문턱값(예: 브레이크 시작 = 압력 10% 이상, 조향 시작 = 일정 각도 이상)은 설정 파일로 두고 리플레이로 맞춘다. 정확한 값은 구현자가 정한다.

### 6.3 기준 랩

- 기준 랩 = 같은 조건의 **내 최고 유효 랩**. AI 상대 세션에서는 **세션 가장 빠른 차의 최고 랩**도 둔다. 둘 중 그 코너에서 더 빠른 쪽을 그 코너의 기준으로 쓴다.
- 가장 빠른 차와 비교할 때는 양쪽에 다 있는 값(위치·속도·페달·스티어)만 쓴다. 휠 슬립처럼 내 차만 있는 값은 내 최고 랩과만 비교한다.
- **서킷별 저장**: 기준 랩과 코너 기록을 SQLite에 저장한다. 키는 서킷 + 조건(모드: 타임 트라이얼 / 레이스 주말, 날씨: 맑음 / 비, 차: 팀 또는 타임 트라이얼 동일 성능)으로 나눈다(마스터 판단).
- 조건이 다른 기준밖에 없으면(예: 레이스 초반 연료가 무거운데 예선 랩과 비교) 시간 차이는 말하지 않고 동작(브레이크 지점, 라인, 스로틀 타이밍)만 말한다.

### 6.4 코너 코칭 (핵심)

- **집중 코너.** 최근 몇 랩(기본 3랩, 설정 가능)에서 기준 대비 시간을 가장 많이 잃는 코너 **4~5개**(사용자)를 집중 코너로 정한다.
  - 레이스 세션에서는 1랩(출발 혼전)을 빼고, 기록이 2~3랩 쌓이면 시작한다(사용자: 경기 중반부터도 해 줄 수 있어야 한다).
  - 저장된 기준이 있는 서킷은 첫 랩부터 저장된 집중 코너로 시작한다(사용자).
- **언제 말하나: 코너를 빠져나온 직후**(사용자). 집중 코너 탈출 지점을 지나면 그 코너에 대해 말한다. 집중 코너가 아니면 말하지 않는다.
  - 예외: 집중 코너가 아니어도 크게 잃었으면(기본 0.3초 이상, 또는 트랙 이탈) 바로 말한다.
  - 다음 코너의 브레이크 지점까지 남은 시간이 짧으면(기본 3초 미만) 다음 긴 직선으로 미룬다. 미뤄도 그 랩 안에 못 하면 버린다.
- **무엇을 말하나: 가장 큰 원인 한 가지.** 그 코너의 지표 중 시간 손실에 가장 크게 작용한 하나만 고른다. 원인 고르는 규칙(예: 브레이크가 늦고 정점 라인이 밖으로 밀렸으면 "브레이크 늦음"이 원인)은 구현자가 리플레이로 다듬는다.
- **개선 알림.** 집중 코너의 손실이 문턱값 아래로 줄면 목록에서 빼고 다음 코너를 넣는다. 그때 한 번 짧게 알린다("3번 좋아졌어. 다음은 7번 보자.").
- **같은 지적 반복**: 고쳐질 때까지 랩마다 다시 말할 수 있지만, 같은 랩에 두 번은 안 한다.

### 6.5 추월 선택지

- **켜지는 조건**: AI 상대 세션에서 앞차와의 간격이 1.0초 이하일 때(설정 가능). 추월하거나 간격이 다시 벌어지면 끈다.
- **판단 재료**: 앞차와의 간격·간격 변화, DRS 사용 가능 여부와 활성 거리, 내 ERS 잔량·모드, 양쪽 타이어 컴파운드·나이, 앞차와 나의 코너별 속도 비교(6.2 기록은 모든 차에 대해 남는다).
- **말하는 것**: 지금 고를 수 있는 선택 1~2개. 예:
  - "앞차랑 0.6초야. 다음 직선에서 DRS랑 ERS 다 써."
  - "앞차랑 0.6초야. 앞차가 9번 탈출이 느려. 9번에서 바짝 붙어서 직선에서 넘어."
  - "앞차랑 0.6초야. 우리 타이어가 6랩 더 새거야. 2랩만 기다렸다가 공격해."
- 한 랩에 추월 무전은 한 번(설정 가능). 코너 코칭과 겹치면 우선순위 규칙(6.7)을 따른다.

### 6.6 위험 경고

- 위험할 때만 음성으로 말한다(사용자). 나머지 상태는 화면에만.
- 대상: 타이어 마모·온도 위험, 연료 부족(남은 랩 < 남은 레이스 랩), 날개·부품 큰 손상, 페널티·경고, SC·VSC·적기, 박스 지시.
- **기준은 한 곳에서만 정한다.** 위험 문턱값과 화면 색 기준을 서버의 설정 하나로 두고, 대시보드 색과 음성 경고가 같은 값을 쓴다(Pacedex 방식 참고). 화면에서 빨간색이 되는 순간이 음성 경고 조건이다.

### 6.7 무전 전달 계층

- 모든 무전은 한 줄의 큐를 거친다.
  - 우선순위: 안전·위험 경고 > 박스 지시 > 코너 코칭 > 추월 > 개선 알림.
  - 동시 발화 금지: 말하는 중에 더 높은 우선순위가 오면 끊고 바꾼다. 낮은 것은 기다리거나 유효 시간이 지나면 버린다.
  - 무전마다 유효 시간을 둔다. 예를 들어 코너 코칭은 그 코너 다음 진입 전까지만 유효하다.
- **말투: 짧은 반말 문장**(사용자 결정 2026-11-14). 무엇이 어땠는지 말하고 어떻게 하라고 이어 준다. 실제 F1 무전처럼 길지 않게 끊는다. 예: "3번에서 브레이크가 늦었어. 5미터 더 일찍 밟아." / "7번 탈출에서 가속이 늦었어. 10미터 더 일찍 밟아." / "앞차랑 0.6초야. 다음 직선에서 DRS 써." / "박스, 박스. 들어와."
- 문장은 틀(템플릿)로 만든다. 틀 목록과 표현은 구현자가 위 예시 말투로 채우고, 사용자 확인을 받는다.
- 무전 끄기: 대시보드에서 무전 종류별로 끌 수 있다(코칭 / 추월 / 경고 / 개선 알림). 안전 경고는 끌 수 없게 한다(마스터 판단).
- 모든 무전을 기록한다(시각, 랩, 코너, 종류, 문장, 근거 수치, 실제 재생 여부·지연). 세션 뒤 화면에서 보여 준다.

### 6.8 음성 합성 (Qwen API)

- **Qwen TTS API만 쓴다**(사용자).
- **지연 목표**: 코너 탈출부터 첫 소리까지 1초 이내. 이를 위해 다음을 한다.
  - **캐시 우선**: 만든 음성은 문장 텍스트(+ 보이스·설정) 기준으로 서버에 저장하고 다시 쓴다.
  - **미리 만들기**: 세션 시작(서킷 확인) 때 그 서킷의 코너 번호 문장, 자주 쓰는 경고, 개선 알림을 미리 만든다.
  - **새 문장은 스트리밍**: 캐시에 없는 문장만 실시간(스트리밍) 모델로 불러 첫 조각부터 재생한다.
- 인터넷이 끊기거나 API가 실패하면 캐시에 있는 문장만 말하고, 대시보드와 무전 페이지에 "음성 오프라인"을 표시한다.
- **무전 효과**: 합성한 음성에 대역 필터, 약한 노이즈, 시작·끝 클릭음을 입혀 F1 무전처럼 들리게 한다. 서버에서 입혀 캐시에 저장한다.
- **보이스 선택**: Qwen이 제공하는 한국어 보이스 몇 개로 같은 무전 문장 샘플을 만들어 사용자가 듣고 고른다(12장 1단계).
- 확인 필요(구현 전): Qwen TTS의 한국어 지원 모델과 보이스 목록, 실시간 모델 단가, 한글 글자 수 계산 방식, 실제 지연.

### 6.9 화면

화면은 서버의 웹 하나로, 태블릿 가로 화면과 옆 모니터를 먼저 맞춘다. 휴대폰은 같은 화면을 세로로 줄여 보여 준다. 화면은 서버 API를 읽기만 한다.

1. **차량 상태**
   - 타이어 4개: 마모 %, 표면·내부 온도, 압력, 컴파운드·사용 랩
   - 브레이크 온도 4개
   - 손상: 앞날개 좌우, 뒷날개, 바닥, 디퓨저, 사이드포드, 기어박스, 엔진, 파워유닛 부품 마모
   - 연료: 남은 양, 랩당 소모, 남은 랩 수
   - ERS: 잔량 %, 모드
   - 색은 6.6의 공통 기준을 쓴다. 값이 잠깐 끊겨도 칸을 지우지 않고 마지막 값을 흐리게 둔다(레이아웃이 흔들리지 않게).
2. **서킷 지도**
   - 트랙 윤곽은 서버가 랩 거리 순 점 배열로 저장한다. 처음 오는 서킷은 내 첫 유효 랩의 위치로 만들고, 서킷별로 저장해서 다시 쓴다.
   - 모든 차를 팀 색 점으로 그린다. 위치는 랩 거리로 윤곽 위를 보간한다(Motion이 없어도 그릴 수 있게).
   - 내 차는 강조, 앞차(추월 대상)는 표시.
   - 집중 코너를 공식 번호와 함께 표시하고, 코너를 누르면 그 코너의 최근 지표(나 / 기준)를 보여 준다.
   - SC·VSC·적기 때 트랙 선 색을 바꾼다.
3. **무전 기록**: 최근 무전 목록(문장 + 근거 수치), 무전 종류별 끄기 버튼.
4. **세션 뒤 코너 리포트**: 코너별 손실 순위, 집중 코너 변화, 무전이 나간 코너와 그 뒤 개선 여부.
5. **상태 표시**: 데이터 수신 상태(6.1 진단), 음성 상태(온라인·오프라인), 무전 페이지 연결 여부.

### 6.10 무전 페이지 `/radio` (게임 PC 브라우저)

- 소리만 내는 페이지다. 화면은 태블릿으로 본다(사용자).
- 브라우저 자동 재생 정책 때문에 처음에 "무전 연결" 버튼을 한 번 누른다.
- 서버와 WebSocket으로 연결해 음성을 받아 재생한다. 끊기면 자동으로 다시 연결하고, 연결 상태를 크게 표시한다.
- 백그라운드 탭이 잠들지 않게 하는 방법(브라우저의 "항상 활성 유지" 등록)을 페이지에 안내한다.
- 마지막 무전 자막을 보여 준다.

### 6.11 데모 송신기 (사용자 요청)

게임을 켜 두고 테스트하기 어려우므로, F1 25 공식 UDP 규격대로 텔레메트리를 쏘는 송신기를 만든다.

- **규격**: EA F1 25 공식 UDP 문서의 구조체를 그대로 따른다(리틀 엔디언, packed, 헤더 29바이트, `packetFormat` 2025). 수신기가 진짜 게임 패킷과 구별하지 못해야 한다.
- **보내는 패킷**: 수신기가 쓰는 종류를 모두 보낸다. Motion, Session, Lap Data, Event, Participants, Car Telemetry, Car Status, Car Damage, Session History, Tyre Sets, Motion Ex, Time Trial. 패킷별 송신 주기는 공식 문서의 주기를 따르고, 기본 60Hz로 하며 설정할 수 있다.
- **서킷**: **스즈카와 모나코**(사용자). 공개 자료로 서킷의 대략적인 중심선, 길이, 공식 코너 번호와 위치를 만든다. 트랙 ID는 공식 문서 값을 쓴다. 다른 앱의 데이터 파일은 쓰지 않는다.
- **주행 모델**: 코너별 목표 속도와 브레이크 지점으로 속도 곡선을 만들고, 중심선을 따라 위치·속도·페달·스티어·기어를 만든다. 물리 시뮬레이터가 아니라 그럴듯한 값을 만드는 정도면 된다.
- **모드**
  - 타임 트라이얼: 내 차 혼자. 랩마다 기록과 Time Trial 패킷을 보낸다.
  - 그랑프리 레이스: AI 차 19대 + 내 차. 차마다 실력 차이를 둔다. 레이스 랩 수를 설정할 수 있다.
- **시나리오 주입**: 코칭·추월·경고를 시험할 수 있게, 정해진 랩·코너에서 상황을 일부러 만든다.
  - 브레이크 늦음(라인 밖으로 밀림), 브레이크 이름, 턴인 이름, 조향 수정, 스로틀 늦음, 트랙 이탈
  - 앞차와 1초 이내 접근, DRS 가능, 앞차가 특정 코너 탈출이 느림, 타이어 나이 차이
  - 타이어 마모·온도 위험, 연료 부족, 앞날개 손상, 페널티, SC·VSC
  - 시나리오는 파일(예: YAML·JSON)로 적고, 시드값을 주면 매번 같은 결과가 나온다(테스트 재현용).
- **실행**: 대상 IP·포트(기본 127.0.0.1:20777), 서킷, 모드, 시나리오 파일, 재생 속도(1배, 빠르게)를 인자로 받는다. 게임 PC가 아니어도 어디서나 실행할 수 있다.
- **주의**: 송신기와 파서를 같은 사람이 같은 규격 이해로 만들면 같은 실수를 공유할 수 있다. 그래서 2단계에서 실제 게임 녹화(타임 트라이얼 몇 랩)를 한 번은 받아 파서를 대조한다.

## 7. 지연 예산 (목표)

| 구간 | 목표 |
| --- | --- |
| 게임 → 서버 UDP | 수 ms (집 네트워크) |
| 코너 탈출 감지 → 무전 결정 | 100 ms 이내 |
| 캐시 적중 → 브라우저 재생 시작 | 200 ms 이내 |
| 캐시 미스 → 첫 소리(스트리밍) | 1초 이내 목표, 실측으로 확인 |

## 8. 테스트

- 녹화한 UDP 리플레이와 데모 송신기(6.11)로 파서·코너 지표·집중 코너·무전 결정을 검증한다(게임 없이). 시나리오마다 "이 무전이 나와야 한다 / 나오면 안 된다"를 테스트로 적는다.
- 첫 녹화는 사용자가 타임 트라이얼 몇 랩과 그랑프리 짧은 레이스를 달려 만든다(구현자가 요청).
- "도움 안 되는 말" 점검: 리플레이 한 번에 나간 무전 목록을 사람이 읽고, 모든 무전이 "어디서 + 무엇을 + 얼마나"를 갖췄는지 본다.

## 9. 나중 단계 (이번 범위 밖, 구조만 열어 둠)

- **무전 질의응답**: 게임이 앞에 있으면 브라우저는 키 입력을 못 받으므로, 누르고 말하기 키와 헤드셋 마이크를 받는 작은 PC 에이전트가 필요하다. 그때 음성 재생도 에이전트로 옮길 수 있게 재생 경로를 한 곳에 모아 둔다.
- UDP 릴레이(다른 앱과 데이터 함께 쓰기), 멀티플레이, 위성 지도 배경.

## 11. 구현자에게 맡기는 것

- 패키지 구조, 웹 프레임워크(또는 표준 라이브러리), 프런트엔드 방식
- 코너 지표 문턱값, 원인 고르기 규칙, 무전 문장 틀(말투 예시를 따르고 사용자 확인)
- 서킷 코너 데이터 파일 형식과 처음 만들 서킷 순서(사용자가 자주 달리는 서킷부터)
- 홈서버 배포 방식(서비스 등록, 포트, 방화벽), 시크릿 전달 방식(`kb/homeserver.md` 참고)
- 녹화 파일 형식

## 12. 단계 (권장 순서)

1. **보이스 샘플**: Qwen 한국어 보이스로 무전 문장 5개 샘플 + 무전 효과 → 사용자가 보이스 선택. Qwen 확인 항목(6.8)도 이때 정리.
2. **수신·파싱·녹화·리플레이** + 진단 정보 + **데모 송신기(스즈카·모나코)**. 실제 게임 녹화로 파서 대조 1회.
3. **대시보드: 차량 상태 + 서킷 지도** + 위험 색 기준.
4. **무전 페이지 + TTS(캐시·스트리밍·무전 효과) + 위험 경고**.
5. **코너 코칭(타임 트라이얼)**: 코너 데이터, 지표, 내 최고 랩 기준, 집중 코너, 탈출 직후 무전.
6. **레이스 확장**: 가장 빠른 차 기준, 추월 선택지, 레이스 세션 규칙.
7. **서킷별 저장**: 조건별 기준 랩 저장, 다음 방문 때 첫 랩부터 코칭, 세션 뒤 코너 리포트.
